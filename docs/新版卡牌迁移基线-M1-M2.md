# 新版卡牌迁移基线（M1–M2）

## 不可违反的实现约束

1. 每个卡牌变体都必须是独立 `DuelCard` Java 类。
2. 同一文物的普通版和金质版必须是两个完全独立的 Java 类，不能共享同一个实现类。
3. 类名、`displayName()` 和迁移文档使用实际文物名称，禁止使用“炎刃”“千钧”等抽象效果名称命名卡牌。
4. 规则可以调用公共工具方法，但卡牌对象和卡牌类本身不能合并为通用数据驱动卡。

## M1 盘点结果

- 实际文物 ID：79 个，权威来源为 `CardCatalog.CARD_IDS`。
- 必须实现的新版卡牌类：158 个（79 个普通版 + 79 个金质版）。
- 当前已实现并注册：12 个类（6 个文物的普通版和金质版）。
- 当前尚缺：146 个独立类。
- 真实中文名称来源：`assets/laigu/lang/zh_cn.json`，并由 `ArtifactCardNames` 在新版规则层建立基线。
- 旧 `DuelCardCatalog` 允许同一文物 ID 在不同批次重复配置，因此它不能直接代表独立文物数量；迁移完整性以 `CardCatalog.CARD_IDS` 为准，旧目录用于提取效果和变体行为。

## M2 已建立的模型和校验

- `CardRarity`：明确普通版和金质版。
- `DuelCard.rarity()`：每个独立类可声明变体，现阶段按 ID 后缀提供兼容默认值。
- `CardMigrationBaseline`：生成 158 个必须存在的新版变体 ID。
- `ArtifactCardNames`：维护 79 个实际文物名称。
- `CardFactory`：注册时校验构造对象、ID 和实际名称非空，并可验证普通/金质实现类不同。
- `CardRegistryValidator`：检查 ID 后缀、稀有度、文物目录、真实名称和变体独立类。
- 自动测试当前明确断言：79 个文物、158 个目标变体、12 个已注册类、146 个缺失类。

## 后续迁移完成标准

当且仅当以下条件同时满足，卡牌类迁移才算完成：

- `CardRegistryValidator.missingVariantIds()` 返回空列表；
- `CardRegistryValidator.validateRegisteredCards()` 返回空列表；
- 注册数量等于 158；
- 每个文物的普通/金质版 `getClass()` 不相同；
- 所有类名都由实际文物拼音名 + `CommonCard` / `GoldCard` 构成；
- 所有 `displayName()` 与实际文物中文名一致，金质版仅追加“·金质”。
