## 2. 当前焦点：卡袋 GUI 背景错位修复（2026-08-23，代码完成+编译过，未启动实测）

### 现象（用户原话）
- 最初：「卡袋的UI的背景有明显的大小错误，远小于实际的UI排版，导致按钮错位」。
- 第一次修后（blit 纹理尺寸 176,168→256,256）：「现在卡袋里面的**前三排没问题了**，但是卡袋**可以放六行物品，而不是三行**，所以下面还是有问题，**横向大小也还有问题**」。

### 根因（已彻底查明）
`minecraft:textures/gui/container/generic_54.png` 是**原版 54 格（6 行）大箱子背景**，不是 3 行。它的精确像素结构（已用 PIL 逐行测量）：

| 贴图 y 区间 | 内容 |
|---|---|
| 0~2 / 214+ | 边框/空白 |
| 3~16 | 标题条（198灰） |
| 17~69 | 容器槽格 行1~3（顶边框 17/35/53） |
| 71~123 | 容器槽格 行4~6（顶边框 71/89/107）← **大箱子多出的 3 行** |
| 125~138 | 物品栏标签条（198灰） |
| 139~191 | 玩家背包槽格 行7~9（顶边框 139/157/175） |
| 193~213 | 快捷栏槽格（顶边框 197，标签 193-196） |

图片 256×256。**vanilla 木桶（27格/3行）绝不全图铺满**，而是（反编译 `ContainerScreen.renderBg` / `m_7286_` 字节码定案）**两段 blit 拼接**：

```java
int topHeight = rows * 18 + 17;   // 3 行 → 71
// 第一段：标题条 + 3 行容器槽格（贴图 0~71）
blit(TEXTURE, leftPos, topPos, 0, 0, imageWidth, topHeight, 256, 256);
// 第二段：从贴图 y=126 起画 96px（物品栏标签 + 玩家背包 3 行 + 快捷栏）
blit(TEXTURE, leftPos, topPos + topHeight, 0, 126, imageWidth, 96, 256, 256);
```

**关键**：第二段 `vOffset=126` 是**硬编码**（不是 `rows*18+17`！字节码里是 `bipush 126`）。它跳过中间大箱子多余的 3 行槽格（71~124），直接用贴图下半部分（126 起）当玩家背包区。槽位对齐逻辑：玩家背包槽(85/103/121) → 贴图 140/158/176（行7~9 槽格内部），快捷栏(143) → 贴图 198。

### 改动文件（已完成）

   - `renderBg()` 从单次 `blit(TEX, leftPos, topPos, 0, 0, imageWidth, imageHeight, 256, 256)` 改为上面的**两段 blit**（用 `this.menu.getRows()`）。
   - javadoc 已更新说明根因。
2. `Laigu\src\main\java\com\laigu\laigu\container\CardPouchMenu.java`

## 2. 当前焦点：骰子收回 / 小局烟花 / 计分音效 / 创造标注（2026-08-23 深夜，代码完成 + 编译过，未启动实测）

### 现象（用户原话 5 条）
0. 备份项目现有内容。
1. 「现在骰子已经放置于卡牌的左侧，但是想收回骰子，可以相应的位置依然在卡牌下侧，而不是左侧对应的位置」。
2. 「小局胜利时，胜利的一方应该也有烟花特效，现在只有决胜局会有胜利者的烟花特效」。
3. 「经常会出现卡牌的跳跃动画和音效时机不匹配的情况，经常反映为音效提前播完，然后卡牌还有多次跳跃动画在后续播放。同时，获得额外分/基础分/倍率时的音效需要做一些区分，可以将其音调进行调整；破阵/激活/激活其他卡/伏击的音效也需要做一些区分，可以换成原版的不同音效」。
4. 「如果玩家获得卡牌时处于创造模式，在卡牌上需要注明：获得于创造模式，斜体灰色」。

### 改动与根因（全部已完成并编译通过）
1. **骰子收回命中区在卡牌下侧**：`renderFieldCard` 把骰子画在卡牌**左侧**竖排（`x+1, y+4+k*(fd+2)`），但 `hitFieldDie` 的命中矩形还在**卡牌底部**（`x+2+k*(fd+2), y+fieldH-fd`），点骰子点不到。**修复**：`hitFieldDie` 命中矩形改为与渲染一致 `x+1, y+4+k*(fd+2)`，尺寸 fd。收回骰子的点击位置与显示位置对齐。
2. **小局胜利无烟花**：烟花只在 `phase==FINISHED && 胜场领先` 时放。**修复**：`advanceScore` 播完计分后把 `roundWinner = v.winnerLast`（服务端**每包都下发**，见 DuelGame.serializeState），`renderScorePanel` 的 `isWinner` 增加 `(phase==ROUND_END && roundWinner==thisSide)`——小局结束（ROUND_END 回合）总分终幕同样在胜利方计分区放烟花，决胜局逻辑不变；终幕结束 `clearFireworks()` 清空粒子、新回合 `roundWinner=-1` 复位。
3. **音效与跳跃错位 + 音效无区分**：旧逻辑每**个步骤**只播一次 `EXPERIENCE_ORB_PICKUP`，而该步骤的 `ticks` 次跳跃动画在后面连续播放 → 音效提前播完。**修复**：
   - 每**次跳跃**（每 tick）播一次短音效：`advanceScore` 每个新 tick（含第一步 `startScorePlayback`）调 `playJumpSound`，音效与卡面跳动严格同步（时长≈1帧）。
   - **音调区分**：仅额外分变化 → pitch 0.9（低沉）；仅倍率变化 → 1.15（高昂）；基础分/混合 → 1.0（`scorePitchFor` 按与上一步的 base/mult/extra 差值判断）。
   - **音色区分**（原版不同音效，`scoreSoundForKind`）：激活(kind=1) → `NOTE_BLOCK_CHIME`（钟声）；伏击(kind=2) → `NOTE_BLOCK_PLING`（拨弦）；破阵(kind=3) → `NOTE_BLOCK_HAT`（短促高音）；普通 → `EXPERIENCE_ORB_PICKUP`。激活达成/伏击/破阵的 kind 均由服务端 ScoreStep 已有字段（1/2/3）下发，「激活其他卡」走激活达成 step（kind=1）同音效。
4. **创造模式标注**：创造物品栏/指令拿的卡没有 `laigu.uid`（开包才 `ensureInstance`）。**修复**：`CardItem.appendHoverText` 当 `uid==null` 时追加 `tooltip.laigu.creative_obtained`，样式 `GRAY + ITALIC`（斜体灰）。新增 lang 键（zh_cn：获得于创造模式 / en_us：Obtained from Creative Mode）。

- `Laigu\src\main\java\com\laigu\laigu\item\CardItem.java`（uid==null → 斜体灰「获得于创造模式」）。
- `Laigu\src\main\resources\assets\laigu\lang\zh_cn.json` / `en_us.json`（新键 tooltip.laigu.creative_obtained）。

## 2. 当前焦点：对局界面 4 项修复（2026-08-23 晚，代码完成 + 编译过，未启动实测）

### 现象（用户原话 4 条）
1. 「发了一次表情之后就不能再发了，打开表情栏后点击表情没有用」。
2. 「log区域有严重问题，信息显示一次后就不刷新了，多行内容杂糅在一起。我不是说做成滚动栏吗？你需要完全推倒重做左侧我方的log区域，对方的log区域不要动！」。
3. 「现在我只能看到我的跳分动画了，看不到对方的；我的卡牌得分动画和右侧计分槽跳分动画对不上；点击部署后右侧计分槽立即就滚动显示完了」。
4. 「胜负播报来的太快了，最后一轮跳分都还没跳完，就显示我已经输了」。

### 根因与修复（全部在 DuelScreen.java / LaiguConfig.java）
1. **表情只能发一次**：`mouseClicked` 里左列 log 拖拽判断（`hit(...leftX0,blueY0,...greenY1-blueY0)`）在最前面，把左下角「表情」按钮和表情面板的点击全吞掉了（按钮/面板都在左列范围）。**修复**：把表情按钮判断与表情面板逻辑移到 log 拖拽判断之前。
2. **log 不刷新/行杂糅**：旧 `renderLogZone` 每个 log 只画一次、按 4+4 均分蓝绿、行高没按换行行数累加 → 多行消息重叠、新消息不出现。**修复**：重写为单块滚动区——把 battleLog 每条按宽度 `wrap` 展开成带颜色的行序列，`logScroll=0` 时取**末尾** visible 行（紧跟最新，每帧重画 → 新消息即时出现），上滚回看历史；蓝区画前若干行、绿区画剩余行，中间黑色大比分条保留（即「对方/比分信息区域不动」）。`clampLogScroll`/`logLinesVisible` 改按换行后总行数计。
3. **看不到对方跳分 / 卡牌与计分槽不同步 / 部署即滚完**：旧右侧只画我方 4 行计分，且 `displayBase(side)` 在无 scoreSteps 时直接读 `lastBase`（部署回合立即显示最终值）。**修复**：右侧下部改为**双方各一个计分区**（对手在上、我方在下，各 4 行：基础/额外/倍率/总分），数值统一走 `displayBase/displayMult/displayExtra`（scoreSteps 逐卡动画插值），并把右列骰池区从 5/5/5/7 压缩为 4/4/4/10，给计分区更大高度；默认积分动画速度倍率 `SCORE_ANIM_SPEED` 从 1.0 降到 **0.55**（纯客户端、可 mod 设置改回），让跳分可见更久、与卡面跳动对得上。
4. **胜负播报过早**：`renderResultBanner` 在 `FINISHED` 一到就显示。**修复**：改为 `FINISHED && !playingScore && scorePlayed` 才显示，等最后一轮跳分动画全部播完再盖遮罩。

- `Laigu\src\main\java\com\laigu\laigu\config\LaiguConfig.java`（scoreAnimSpeed 默认 0.55）。

## 3. 关键坑（踩过并验证，写代码前先看）

**Gradle / 构建**
- `gradle.properties` 按 ISO-8859-1 读，中文必须写 `\uXXXX` 字面转义（`\u6765\u53e4\u724c`=来古牌）。`build.gradle` 的 processResources 已设 `filteringCharset='UTF-8'`，勿删。
- gradle daemon 僵死 → `./gradlew --stop` 再重跑。

**1.20.1 客户端渲染**
- `GuiGraphics.blit` 6 参数重载默认按 **256×256** 算 UV；非 256 贴图必须用 9 参数显式传纹理尺寸，否则贴图只显示左上角被放大。**纹理尺寸参数 = 图片实际像素**，uWidth/vHeight = 屏幕显示尺寸。
- `AbstractContainerScreen.render()` 基类**不调** `renderTooltip`；自定义容器屏须覆写 render：`renderBackground` → `super.render` → `this.renderTooltip`。
- **`Font.adjustColor()` 会把 alpha 字节 <4 的颜色强制改写为全不透明**（`if ((color & 0xFC000000)==0) color|=0xFF000000`）——淡入淡出末尾 alpha≈0 会闪成不透明。修法：`alphaByte<4` 即停画。
- `RenderLevelStageEvent` 只分发 `AFTER_SKY/AFTER_ENTITIES/AFTER_BLOCK_ENTITIES/AFTER_PARTICLES/AFTER_WEATHER` 五个 stage；`AFTER_TRANSLUCENT_BLOCKS` 有枚举但**从不分发**，监听=永不渲染。用 `AFTER_PARTICLES`。
- 端详 3D 牌框：物品模型 override + `ItemProperties.registerGeneric` predicate（`laigu:inspecting`）。模型固定 +Z 朝向世界南，要绕视线轴自旋须列基 `Matrix3f(right.x,up.x,-fwd.x,...)` + `Quaternionf.setFromNormalized`。

**网络**
- `ModPackets` 客户端方向包用 `unsafeRunWhenOn(Dist.CLIENT,...)`，**别用 `safeRunWhenOn`**（对捕获 lambda 变量做安全检查会误报 FATAL「Detected unsafe referent usage」且动画不播）。
- 客户端侧位（A/B 侧）必须经 `openScreen` 网络缓冲传（`IForgeMenuType.create`），不能只靠客户端 BE 的 NBT（服务端改后不推送）。
- 开包动画：`ItemStack packVisual = stack.copy()` 先 copy 再 `stack.shrink(1)`，否则发出去的是空栈。

**联机双开**
- 两边都 `./gradlew runClient`：主机默认 `run/`；客机 `./gradlew runClient -PlaiguClientDir=run-client2 --args="--username Player2"`（build.gradle 里 client 配置已支持 `workingDirectory` 分目录）。
- **别用自定义 run 配置名**（client1/client2 已删）：ForgeGradle 只给标准名套完整启动参数。
- 别让 `run-client2/mods/laigu-dev.jar` 躺在那（旧 jar 会被选中导致注册表握手失败）——双开方案已不需要它。
- 别加载旧存档（`run/saves/` 旧世界会注册表错位），隔离办法是把旧档移出 `saves/`。

**其他**
- `Set.of()` 里枚举必须写限定名 `EffectType.X`（裸枚举名只在 switch case 标签合法）。
- `SoundEvents.*` 个别是 `Holder.Reference<SoundEvent>`（如 `NOTE_BLOCK_CHIME`），传 `playSound` 须 `.value()`。
- 按钮**任何状态都绝不禁用**（`active=false`=按下贴图，用户反复反馈「按钮卡住」）。用槽位高亮表达确认态。
