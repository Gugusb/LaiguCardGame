# 新版卡牌效果重构交接任务清单

## 一、项目目标

将 Laigu 的新版卡牌效果系统重构为“接口式多词条架构”。

每张卡牌根据自身效果选择需要实现的接口：

- 入场
- 离场
- 激活
- 回合开始
- 回合结束
- 回合结算
- 伏击成功
- 伏击失败
- 破阵
- 抢骰或抓骰

一张卡牌可以同时实现多个接口。

示例：

```java
public final class ExampleCard
        implements DuelCard, OnSummon, OnActivation, OnRoundEnd, OnSettlement
{
}
```

不使用的接口不实现，不保留空方法。

## 二、不可违反的设计原则

### 1. 每张卡牌必须是独立类

每个实际文物都必须有自己的普通版类和金质版类。

例如：

```text
QianLiJiangShanCommonCard
QianLiJiangShanGoldCard
```

禁止使用以下方式代替独立类：

- 通用卡牌类加配置参数；
- GenericCard；
- CardDefinition 直接实例化；
- 一个类通过 ID 判断所有卡牌效果；
- 用“炎刃”“千钧”“磐石”等抽象效果名作为卡牌身份。

### 2. 普通版和金质版必须是不同类

普通版和金质版必须满足：

```java
common.getClass() != gold.getClass()
```

两者可以复用公共判断工具和公共机械方法，但不能使用同一个卡牌实现类。

### 3. 卡牌名称必须使用实际文物名称

卡牌类名和 `displayName()` 使用实际文物名称。

示例：

```text
TongCheMaCommonCard
displayName() -> 铜车马
```

禁止：

```text
YanRenCard
displayName() -> 炎刃
```

### 4. 一张卡可以拥有多个词条

卡牌效果不能被限制为一个主效果。

禁止把整张卡设计成：

```java
EffectType settlementEffect();
int effectP1();
int effectP2();
```

这种单效果结构最多只能作为旧版迁移兼容层，不能作为新版最终模型。

## 四、阶段五：多词条效果接口框架

### 5.1 创建独立触发接口

每个接口使用单独的 public Java 文件。

建议文件：

```text
OnSummon.java
OnLeave.java
OnRoundStart.java
OnRoundEnd.java
OnActivation.java
OnSettlement.java
OnAmbushSuccess.java
OnAmbushFail.java
OnPoZhen.java
OnDraft.java
OnPlace.java
```

接口示例：

```java
public interface OnSummon
{
    void onSummon(CardContext context);
}
```

```java
public interface OnActivation
{
    int activationThreshold();

    void onActivation(CardContext context);
}
```

```java
public interface OnSettlement
{
    void onSettlement(SettlementContext context);
}
```

接口要求：

- 方法名必须体现触发时机；
- 不要所有接口都使用 `execute()`；
- 不实现的接口不需要空方法；
- 接口本身只定义触发契约；
- 具体摸牌、加分、判定等动作使用公共工具完成。

### 5.2 修改 `DuelCard`

`DuelCard` 只负责基础卡牌身份：

```java
String id();
String displayName();
CardClass cardClass();
CardRarity rarity();
```

新版卡牌的主要效果通过接口表达：

```java
card instanceof OnSummon
card instanceof OnActivation
card instanceof OnSettlement
```

`CardEffect` 和 `LegacyMappedCard` 暂时保留用于兼容已经写入的旧迁移代码，但新卡牌不得继续依赖单一 `settlementEffect()` 模型。


如果当前代码不适合创建多个上下文类，可以先使用现有：

```text

```

但必须保证不同触发阶段能获得所需的数据。

上下文至少应支持：


### 5.4 建立公共机械效果

公共工具只封装具体机械动作，不代表完整卡牌。

建议：

```text
CardEffects.drawCards()
CardEffects.addBaseScore()
CardEffects.addMultiplier()
CardEffects.addExtraScore()
CardEffects.activateCard()
CardEffects.restoreActionPoints()
CardEffects.markDestroyAtRoundEnd()
CardEffects.destroyCard()
```

骰型判断：

```text
DicePatterns.isStraight()
DicePatterns.isAllHigh()
DicePatterns.isAllLow()
DicePatterns.isAllOdd()
DicePatterns.isAllEven()
DicePatterns.isTwoPair()
DicePatterns.isFullHouse()
DicePatterns.isAllSame()
DicePatterns.sum()
```

场面判断：

```text
FieldConditions.hasAdjacentCard()
FieldConditions.hasSameDynasty()
FieldConditions.hasSameClass()
FieldConditions.hasGoldCard()
FieldConditions.opponentFieldFull()
FieldConditions.isIsolated()
```

公共工具只负责：

```text
执行动作
或判断条件
```

不要让公共工具代替独立卡牌类。

### 5.5 修改事件派发

`BattleEventDispatcher` 按接口派发：

```java
if (event.type() == BattleEvent.Type.SUMMON
        && card instanceof OnSummon handler)
{
    handler.onSummon(context);
}
```

```java
if (event.type() == BattleEvent.Type.LEAVE
        && card instanceof OnLeave handler)
{
    handler.onLeave(context);
}
```

```java
if (event.type() == BattleEvent.Type.ROUND_END
        && card instanceof OnRoundEnd handler)
{
    handler.onRoundEnd(context);
}
```

```java
if (event.type() == BattleEvent.Type.ACTIVATION
        && card instanceof OnActivation handler)
{
    handler.onActivation(context);
}
```

```java
if (event.type() == BattleEvent.Type.SETTLEMENT
        && card instanceof OnSettlement handler)
{
    handler.onSettlement(context);
}
```

必须防止重复执行：

- 如果新版接口已经执行某个效果，旧版事件注册表不能再执行同一个效果；
- `FrameworkFiveEventRules` 只能作为兼容迁移路径；
- 未来完全迁移后，应移除对应旧事件注册；
- 一个事件只允许执行一次。

### 6.2 自定义计数器

支持卡牌 B 这类复杂效果：

```text
初始 a = 0
入场 a += 1
激活 1 a += 1
回合结束时牌型为顺子 a += 1
回合结算基础分 += a
```

建议 API：

```java
int counter(String name);
void addCounter(String name, int amount);
void setCounter(String name, int value);
```

上下文中提供：

```java
context.counter("a").value();
context.counter("a").add(1);
context.counter("a").set(0);
```

要求：

- 计数器属于具体卡牌实例；
- 不同卡牌实例之间不能共享；
- 普通版和金质版各自拥有自己的计数器；
- 计数器不能为负数；
- 计数器可以跨回合保存；
- 状态保存和读取必须包含计数器。

### 6.3 明确状态生命周期

默认采用以下语义：

```text
卡牌入场：
    创建该卡牌实例状态

同一张卡牌在场期间：
    状态跨回合保留

卡牌离场：
    该实例状态清除

同一 ID 重新入场：
    视为新的卡牌实例
```

如果某张卡有“离场后重新入场仍保留”的特殊规则，再单独实现本局持久状态。

### 6.4 回合执行顺序

统一顺序：

```text
1. 抢骰或抓骰
2. 放置卡牌
3. 入场 OnSummon
4. 激活 OnActivation
5. 回合结束 OnRoundEnd
6. 回合结算 OnSettlement
7. 执行消耗和离场
8. 清除本轮临时状态
9. 进入下一回合
```

卡牌 B 的执行结果：

```text
入场：
    a += 1

激活 1：
    a += 1

回合结束且顺子：
    a += 1

回合结算：
    基础分 += a
```

注意：

```text
回合结束顺子判断必须发生在清除骰子之前。
```
