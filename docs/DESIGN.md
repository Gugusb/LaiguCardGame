# 来古牌（Laigu）设计文档

> 本文档汇总已有贴图资产与卡牌系统设计方向，供后续开发参考。

## 一、核心玩法

服务器后期玩家痛点：**神装收集完了、挑战打完了，不知道干什么。**

来古牌的目标：把「**集齐全套卡牌**」做成后期长期目标。

- 开卡包获得随机卡牌
- 稀有度分级：普通（common）/ 金质（gold）/ 钻石（diamond）
- 有图鉴可查：已收集 / 未收集 / 缺哪张一目了然
- 获取途径与后期玩法挂钩，让玩家"有事可做"

## 二、已有美术资产（`Wuhuamixian/像素画头像_64x64/`）

### 卡面
- **79 张** 64×64 中式文物主题像素卡面（千里江山图、亚长牛尊、曾侯乙编钟、敦煌飞天、断臂维纳斯、星月夜……中西文物混搭）
- 卡面规格：64×64，卡面区域 **38×57**（2:3 纵长）居中
- 输出命名：`{中文名}_普通版.png` / `{中文名}_金质版.png`
- 卡牌输出目录已有 **250** 个文件（79×2 + 模板/预览/对比图）

### 边框 / 稀有度
- **普通版**：V2 边框——3px 厚边 + 木纹肌理 + 雷纹角饰（木褐色系）
- **金质版**：V1 边框——2px 细边 + 云纹角饰 + 金属高光（金色系）
- 钻石版：由卡面明暗程序化换色生成（`make_gold_v2.py` 等脚本）

### 卡包
- 四种卡包贴图：**普通、末影、炫彩、金质**（`_tmp_packs/卡包_*_orig.png`）
- `make_card_packs.py`：卡包合成脚本

## 三、卡牌数据结构（建议）

数据驱动，卡片本体用**一个通用物品 + NBT 区分具体卡**，避免注册表爆炸：

```jsonc
// assets/laigu/card_defs/ 下按卡分文件，或集中一张 registry.json
{
  "id": "qianli_jiangshan",        // 唯一 id，ASCII
  "name": "千里江山图",              // 中文名
  "rarity": "gold",                // common | gold | diamond
  "texture": "laigu:card/qianli_jiangshan",  // 卡面贴图（合成后的整卡贴图）
  "lore": "北宋王希孟作，青绿山水典范",        // 简介/出处
  "source": "ancient_city_loot",   // 来源标注，供图鉴展示
  "weight": 5                      // 开包权重
}
```

卡物品建议：
- `laigu:card` —— 通用卡牌物品，NBT 记录 `card_id` 与稀有度
- `laigu:card_pack_common` / `card_pack_ender` / `card_pack_rainbow` / `card_pack_gold` —— 四种卡包

渲染建议：物品用 `ItemOverrides`/模型覆盖或自定义 `IClientItemExtensions`，按 NBT 动态选择贴图。
（卡片贴图可直接用贴图管线产出的整卡 64×64 PNG，MC 物品 16×16 显示会缩小，需评估清晰度；备选：用 16×16 卡牌图标。）

## 四、图鉴系统（建议）

- **数据存储**：服务端按玩家 UUID 存 `Set<cardId>`（或 BitSet）到 `data/laigu/<uuid>.json`
- **查看**：手持图鉴物品右键打开 GUI；或卡牌界面列出所有卡（已收集亮、未收集暗）
- **进度**：集齐 X 张解锁成就 / 特殊奖励，作为后期目标锚点

## 五、获取途径（建议，与后期玩法挂钩）

| 途径 | 说明 |
|------|------|
| Boss 掉落 | 末影龙、凋灵、远古守卫者等 |
| 结构战利品 | 古城、海底神殿、末地城箱子 |
| 考古 | 刷子刷可疑方块 |
| 钓鱼 | 稀有卡小概率 |
| 村民交易 | 大师级村民换卡 |
| 掉落怪 | 刷怪塔副产品（普通卡） |
